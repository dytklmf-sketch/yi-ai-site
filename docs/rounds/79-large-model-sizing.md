# 第七十九轮：选型参考改为主流大模型（2026-10-08）

## 站长要求

基础设施页「选型参考」：客户一般要部署 Kimi K3 这类很大的模型，原来 7B–70B 的举例不够。

## 实际改动

- `infra-detail.ts` `infraSizing`：表头改为「模型 / 总参数与激活参数 / 官方权重 / 推理部署参考」，按规模从大到小列 6 个主流开源 MoE
  模型，7B–70B 合并为最后一行「70B 及以下」：

  | 模型              | 总 / 激活   | 官方权重             | 推理部署参考                                |
  | ----------------- | ----------- | -------------------- | ------------------------------------------- |
  | Kimi K3           | 2.8T / 104B | MXFP4，约 1.56 TB    | 单机 8 张 288 GB 级；或 2 台 8 张 141 GB 级 |
  | Qwen3.8-2.4T      | 2.45T / 95B | FP8，约 2.5 TB       | 2 台 8 张 192 GB 级起；长上下文 288 GB 级   |
  | DeepSeek-V4-Pro   | 1.6T / 49B  | FP4 + FP8，约 865 GB | 单机 8 张 141 GB 级起；长上下文 192 GB 级   |
  | GLM-5.2           | 753B（MoE） | FP8，约 761 GB       | 单机 8 张 141 GB 级；或 2 台 8 张 80 GB 级  |
  | Qwen3.5-397B      | 397B / 17B  | FP8，约 406 GB       | 单机 8 张 80 GB 级                          |
  | DeepSeek-V4-Flash | 284B / 13B  | FP4 + FP8，约 160 GB | 4 张 80 GB 级；或 2 张 141 GB 级            |

- 数据来源：参数与权重格式取各模型 Hugging Face 官方模型卡；权重大小取 Hugging Face API 的已发布文件大小
  （`usedStorage`）。GLM-5.2 官方卡未写激活参数，只写总参数，不采用第三方文章的数字。
- 部署参考算法：权重 × 约 1.2（KV 缓存与运行余量）对照单机 8 卡的单卡显存档位（80 / 141 / 192 / 288 GB）；不写具体 GPU 型号。
- 备注新增「MoE 模型按总参数占显存」，并说明百万级上下文与并发会需要更多显存。
- 重新生成中文字体子集（`font-guides.css` 随之更新）并还原拉丁字体。
