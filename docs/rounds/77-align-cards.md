# 第七十七轮：代码卡去掉横向滚动条，计费卡与适用场景对齐（2026-10-07）

## 站长要求

1. 模型服务页页首右侧代码卡片，大屏幕下出现左右拉的滚动条，不应该出现。
2. 「接入与计费」里的计费方式卡片，内容居中并和左侧卡片对齐。
3. 所有页面的「适用场景」，左右两侧卡片对齐。

## 原因

1. 页首示例的字号随屏幕宽度放大（`.sample-stage` 用 vw），但窗口最宽只到 44rem；英文 1680 宽起、中文 2560 宽时，
   最长一行代码比窗口宽，`overflow-x: auto` 就出了滚动条。
2. 两张卡等高，但计费卡内容都堆在上面，公式框与底部链接之间空一大块。
3. 「适用场景」标题放在左列里，右侧「合作范围」对整个左列垂直居中，于是上下边都对不齐。

## 实际改动

- `site.css`：`.api-card` 设为尺寸容器，代码字号再加一个上限 `100cqi / 37`（最长一行 54 个等宽字符加左右内边距）。
  1280 宽以下不变；手机仍保留 11px 下限，照旧可横向滑动。
- `site.css`：桌面（≥1081px）计费四行平分卡片高度，每行内容垂直居中；底部链接与左侧「常用工具」一行齐平。
- `[slug].astro`：「适用场景」标题移出两列，单独占一行；`.split-fit` 改为 `align-items: stretch`，
  左侧四张卡与右侧合作范围顶边、底边对齐，较矮的一侧拉伸（卡片行或合作范围白框）。
  `.boundary-note` 在其他地方有 `flex: 0 1 26rem`，在纵向面板里会被当成高度，这里重置为 `flex: none`。
- 只有三个业务页有「适用场景」，三页（中英共 6 页）一起生效。

## 测试

- 测量脚本（1280×800、1440×900、1680×1050、1920×1080、2560×1440，6 页）：代码区 `scrollWidth` 全部等于
  `clientWidth`（修改前英文 1680 起、中文 2560 溢出）；适用场景左右两侧顶边、底边逐像素一致；计费卡与左卡等高。
- `pnpm check`、`pnpm build`、`pnpm test` 通过；`pnpm test:quick` 6 页通过。
- 完整 `pnpm test:browser`：通过：320 项响应式页面检查、80 次 axe 扫描、59 个内链、交互与无 JS 路由；Chromium 与 WebKit
  增强流程、动效录屏、减少动态效果与重排。

## 遗留

- 手机上代码卡仍可横向滑动（原有设计，字号再小不可读）。
