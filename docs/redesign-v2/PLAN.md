## 1. 为什么要重来，这次怎么避免同样的问题

上一轮反复修不好，原因有三个：

1. **样式叠加打架。** 新写的深色样式放在新文件里，去覆盖 `home-chapters.css` 里原有的首屏规则。原规则选择器更具体，还分散在 5 个断点里，改一处漏一处。例如 `.home-story .home-chapter > .site-container { flex-direction: column }` 一直在压着首屏的横向布局。
2. **布局方法不对。** 用 flex 的 `order` 和换行去拼"左边两块、右边一块"，这是二维布局，flex 天生做不好，所以鲸鱼一直无法真正居中。
3. **没有自己看效果。** 每一轮都靠你截图反馈，我在凭推断改 CSS。

这一轮的做法：

- **重写，不覆盖。** 首屏样式集中到一个新文件，同时把 `home-chapters.css` 里所有旧的首屏规则删掉，不再留两套规则互相压。
- **首屏用 CSS Grid。** 用 `grid-template-areas` 直接声明"左上文字、左下卡片、右侧鲸鱼跨两行居中"，不再依赖 `order`。
- **每一步都自己截图检查。** 用项目里已有的 Playwright，在 6 个尺寸下截图，并用脚本自动检查元素是否重叠、是否横向溢出、鲸鱼是否居中。截图我自己看过、确认没问题，才会交给你。

## 2. 现状诊断（基于 main 版本实测）

基线截图在 [`baseline/`](./baseline/)：1920×1080、1440×900、1366×768、390×844。

实测数据（Chromium，本机开发服务器）：

| 视口      | 逐屏翻页是否启用 | 首屏高度 | 服务章节高度 | 备注                                    |
| --------- | ---------------- | -------- | ------------ | --------------------------------------- |
| 1920×1080 | 是               | 999px    | 999px        | 内容偏窄，左右留白很大                  |
| 1440×900  | 是               | 819px    | 851px        | 服务章节比一屏高，翻页时会先在章节内滚  |
| 1366×768  | 否（高度 < 800） | 712px    | 869px        | 和大屏是两套滚动行为                    |
| 390×844   | 否               | 732px    | 2013px       | 底部悬浮按钮挡住了"01 / 我们的服务"提示 |

### 2.1 滚轮卡顿的根因

1. **滚轮被脚本接管。** `src/scripts/chapter-navigation.ts` 在 `window` 上注册了 `passive: false` 的 `wheel` 监听，并且调用 `preventDefault()`。这样浏览器就不能在合成线程上直接滚动，每一次滚轮输入都要等主线程的 JS 处理完，这是"不跟手"的主要来源。
2. **固定时长动画加冷却期。** 每次翻页是 640–1000ms 的脚本动画，结束后还有 600ms 冷却期，冷却期内小幅滚动会被吞掉。用户感觉是"滚了没反应"或"一顿一顿"。
3. **不同屏幕两套行为。** 逐屏翻页只在宽 ≥1200、高 ≥800、精细指针时启用。1366×768 这类小屏笔记本完全不翻页，同一个网站在两台显示器上手感不同。
4. **章节比一屏高时逻辑变复杂。** 1440×900 下服务章节是 851px，比可视区 819px 高，脚本要先在章节内部滚完才翻页，容易出现"停在两屏中间"或"突然跳"。
5. **导航栏模糊。** 吸顶导航用了 `backdrop-filter: blur(16px)`，滚动时每帧都要重新模糊下面的内容，是额外的绘制开销。

### 2.2 小屏显示问题

- **按屏幕高度隐藏内容。** 在高度 800–860 的桌面窗口里，CSS 会隐藏服务卡片的"准备材料"和指南卡片的预览列表。同一份内容，屏幕小的人看到的更少。
- **首屏在 1366×768 下很挤**，底部的"下一章"提示被裁掉一半。
- **手机端**首屏的"01 / 我们的服务"提示被底部固定的"咨询合作"按钮挡住；服务章节 2013px，三张卡片一路往下排，阅读成本高。

### 2.3 视觉层面

- 浅蓝底、白卡片、每节都有一样的"01 / xxx"小标签，整体偏模板感，缺少让人记住的视觉时刻。
- 鲸鱼标识只是一张静态 PNG，没有发挥品牌资产的作用。
- 动效只有淡入，"高级感"主要来自排版和节奏，现在两者都不够。

### 2.4 GEO（让 AI 搜索引擎能读懂、能引用）

- 结构化数据目前只有 `WebSite`、`Brand`、`Organization`、`Article`，缺 `FAQPage`、`Service`、`BreadcrumbList`。
- 没有 `llms.txt`。
- 全站是 `noindex`，这是有意的（正式域名确认前不开放收录），本轮不改。GEO 相关工作本轮做好准备，上线时一起生效。

## 3. 用户侧：谁来访问、他们要完成什么

### 3.1 三类访客

| 访客             | 他们是谁                           | 进站后最想知道                           | 主要入口        | 期望的下一步                     |

### 3.3 用户旅程（以企业采购为例）

1. 从搜索或别人转发的链接进入首页，首屏看到"易AI · 让 AI 真正用起来"和三张卡片。
2. 点"给团队选一款 AI 工具"，进入 WorkBuddy 页面。
3. 在页面第一段看到直接回答：易AI 是 WorkBuddy 代理商，可以沟通版本、授权和采购条件。
4. 往下看"需要准备什么材料""报价取决于什么""服务边界"，判断是否值得联系。
5. 点"咨询 WorkBuddy"，进入联系页，业务方向已自动选好 WorkBuddy。
6. 复制微信号或发送带主题的邮件，完成转化。

另外两类访客的路径相同，只是第 2 步点的卡片不同。改版要保证这条路径上每一步都更短、更清楚，而不是把首页做得更花。

### 3.4 文案调整原则

- **不新增任何事实。** 不写客户案例、价格、SLA、资质、数字。只用 `src/data/zh.ts`、`en.ts` 里已确认的内容。
- **首屏一句话定位**保持"让 AI 真正用起来，在业务中落地"。
- **每个业务页第一段改成直接回答**，句式是"易AI 提供 xxx，适合 xxx，可以沟通 xxx"。这对访客和 AI 搜索都更友好。
- **减少重复的小标签。** "01 / 我们的服务"这类标签只在真正有顺序的地方保留（合作流程、首屏路由卡片），其他章节去掉编号。
- **按钮文字写清楚动作。** "咨询合作"在业务页改成"咨询 WorkBuddy"这类具体说法。

### 3.5 GEO：让 AI 搜索能读懂、能引用

本轮全部做好，但在去掉 `noindex` 前不会生效：

1. **可见文字优先。** 每个业务页第一段是一句能被直接引用的完整回答，不依赖上下文。
2. **FAQ 结构化数据。** 首页和业务页的常见问题输出 `FAQPage`，内容和页面上显示的文字完全一致。
3. **业务结构化数据。** 三个业务页各输出一个 `Service`，`provider` 指向易AI 的 `Organization`。只填已确认的字段，地址、服务区域这类未知信息不填。
4. **面包屑。** 内页输出 `BreadcrumbList`。
5. **文章元数据。** 指南输出 `datePublished`、`dateModified`，作者为易AI。
6. **`llms.txt`。** 准备一份站点摘要和关键页面清单的模板。因为正式域名未定，链接需要绝对地址，所以上线时再生成最终版本。
7. **命名统一。** 全站只用"易AI / Easy AI"两个名字，不出现其他写法。

深浅节奏（按选项 A）：首屏深 → 服务浅 → 能力深 → 流程浅 → 指南浅 → 问题浅 → 联系深 → 页脚浅。深色不超过三处，避免压抑。

### 4.5 内页

本轮以首页为主，内页只做和首页一致的调整：

- 业务页：页头改为"直接回答"段落 + 右侧目录；统一新的字号阶梯和内容宽度。
- 关于、资源列表、文章、联系页：套用新的颜色、字号和宽度，不改结构。
- 404：套用新样式即可。

### 4.6 动效规范

原则：只动 `transform` 和 `opacity`，不做滚动劫持，不做循环动画，鲸鱼只在首屏载入时动一次（`BRAND.md` 要求）。

| 场景         | 触发         | 效果                                     | 时长                        | 减少动态效果时 |
| ------------ | ------------ | ---------------------------------------- | --------------------------- | -------------- |
| 鲸鱼标识     | 首次载入     | 四条路径依次描边，描到 60% 时开始填色    | 共约 1000ms，一次           | 直接显示       |
| 首屏文字     | 首次载入     | 品牌名、主张、简介、按钮依次淡入上移 8px | 每项间隔 80ms，总计 ≤ 700ms | 直接显示       |
| 路由卡片     | 首次载入     | 在文字之后依次淡入                       | 总计 ≤ 900ms                | 直接显示       |
| 章节标题     | 滚动进入视口 | 淡入上移 12px                            | 由滚动进度驱动              | 直接显示       |
| 卡片组       | 滚动进入视口 | 最多 3 张依次淡入，间隔 60ms             | 400ms                       | 直接显示       |
| 流程连接线   | 随滚动       | 连接线从左到右画出，经过的节点亮起       | 由滚动进度驱动              | 直接显示完整   |
| 卡片悬停     | 鼠标悬停     | 上移 4px，边框变蓝，箭头右上移 2px       | 180ms                       | 只变颜色       |
| 服务卡片描边 | 鼠标悬停     | 一道蓝色光沿边框走一圈，只走一次，不循环 | 900ms                       | 不显示         |
| 按钮按下     | 点击         | 缩放到 0.98                              | 120ms                       | 不缩放         |
| 常见问题展开 | 点击         | 高度展开并淡入（保留现有实现）           | 220ms                       | 直接展开       |
| 复制微信     | 点击         | 图标变成对勾，出现"已复制"文字           | 180ms                       | 只换文字       |
| 页面跳转     | 同站链接     | 原生页面过渡（保留现有实现）             | 180ms                       | 关闭           |

"由滚动进度驱动"的动画用 CSS 的 `animation-timeline: view()` 实现，完全不用 JS 监听滚动，所以不会影响滚动流畅度。不支持的浏览器退回到 `IntersectionObserver` 触发的一次性淡入。

明确不做：视差、粒子背景、持续漂浮或旋转、自定义鼠标、滚轮接管。

### 4.7 滚动方案（按选项 A）

- 删除 `chapter-navigation.ts` 的滚轮接管和逐屏翻页逻辑，删除所有 `scroll-snap`。
- 章节高度按内容自然撑开，上下留白桌面 96–120px。只有首屏是整屏高度。
- 右侧目录点保留：用 `IntersectionObserver` 高亮当前章节（不再每帧计算位置），点击后用原生平滑滚动跳到对应章节，滚动过程中用户随时可以打断。
- 键盘 PageUp / PageDown / 空格 / Home / End 全部走浏览器原生行为。
- 如果你选 B（保留逐屏翻页）：只用 CSS `scroll-snap-type: y proximity`，不写任何滚轮 JS；而且只在所有章节内容都放得进一屏时才启用。这个方案必须在实体触控板上测过才交付。

### 4.8 无障碍和性能底线

- 所有文字对比度 ≥ 4.5:1，大标题 ≥ 3:1，用脚本逐项测。
- 键盘可以访问所有交互，焦点样式清晰可见。
- 屏幕阅读器的阅读顺序：文字 → 路由卡片 → 其他内容，鲸鱼标识标记为装饰。
- 减少动态效果模式下关闭所有位移动画。
- 无 JavaScript 时所有内容可读、所有链接可用。
- 每页可执行 JS 总量保持在 20KB 以内（现有预算）。
- 首屏鲸鱼 SVG 内联，不额外发请求。

### 5.3 自动检查脚本 `scripts/shoot.mjs`

每次改动后运行，在以下 6 个尺寸截图：1920×1080、1440×900、1366×768、1024×768、768×1024、390×844，中英文各一套。自动检查：

1. **重叠检查**：首屏文字、路由卡片、鲸鱼三个区域的边界框两两不相交。
2. **居中检查**：鲸鱼的垂直中心和"文字 + 卡片"整体的垂直中心相差不超过 16px（桌面尺寸）。
3. **溢出检查**：页面宽度不超过视口宽度，没有横向滚动。
4. **遮挡检查**：手机端底部固定按钮不遮挡任何可点击元素。
5. **内容一致性**：所有尺寸下"准备材料"等内容都存在，不因屏幕高度被隐藏。
6. **滚动流畅度**：模拟滚轮滚过整个首页，记录每帧间隔，桌面尺寸 95% 的帧间隔 ≤ 20ms。这是本机实验室数据，不代表真实用户，但可以用来对比改动前后。
7. **对比度**：对首屏和深色章节的文字逐项计算对比度。

截图输出到 `docs/redesign-v2/after/`，和 `baseline/` 对照。
