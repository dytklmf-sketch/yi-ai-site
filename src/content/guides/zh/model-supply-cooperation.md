适用于有权提供相关资源、能够说明合作范围的供应伙伴，以及需要建立采购核对流程的需求方。如果供应依据、使用权限或数据处理责任存在疑问，应先核实，不以小额测试替代授权确认。

## 首次沟通的六项材料

1. **合作角色**：联系人及其负责范围，资源持有方与实际提供服务的一方是否一致。
2. **资源范围**：模型标识、接口形式、输入输出类型、服务地区与可提供周期；未确认项应明确标注。
3. **供应依据**：可以核验的使用与供应权限，哪些资料可在适当的保密安排下进一步核对。
4. **容量约束**：调用频率、Token 限制、并发和计划维护窗口。按条件描述，不只给一个总量。
5. **计费结算**：计量单位、周期、对账样例、异常扣费争议处理及价格变更通知方式。
6. **责任与退出**：异常联系窗口、数据和日志处理、暂停条件、未完成任务及剩余额度如何处理。

速率限制的官方参考说明了「总量」和「单位时间可调用量」的区别，但具体供应额度必须由实际提供方确认。

## 资源说明样例

下表是虚构的资源说明，模型名与数字均为占位。

| 栏目              | 填写示例                                                    |
| ----------------- | ----------------------------------------------------------- |
| 模型标识          | 〈模型名〉，版本〈日期或编号〉                              |
| 接口形式          | OpenAI 兼容 Chat Completions，支持流式输出                  |
| 输入输出          | 文本输入、文本输出；不含图片输入                            |
| 上下文 / 输出上限 | 按官方模型说明，附链接                                      |
| 容量              | 每分钟请求数〈数值〉，每分钟 Token 数〈数值〉，并发〈数值〉 |
| 维护窗口          | 每周〈时间段〉，提前〈天数〉通知                            |
| 可提供周期        | 〈开始日期〉至〈结束日期〉，续期条件〈说明〉                |
| 计量与结算        | 按接口返回的用量字段计量，按月对账                          |
| 异常联系          | 工作日〈时间段〉，联系人〈角色〉                            |
| 供应依据          | 可在保密安排下核验的材料清单                                |

尖括号里的内容由供应方按实际情况填写；不知道的写「待确认」，不要估一个数。

## 验证与推进顺序

1. **核对身份与依据**：确认联系人、资源持有方与供应依据。
2. **约定有限测试**：目标、样本、费用、数据范围与调用频率。
3. **执行测试**：只使用经批准的样本和独立测试凭据，不在普通聊天或文档里传生产密钥。
4. **汇总结果**：兼容性、错误类型、延迟与计量差异，标出已解决和待确认的问题。
5. **商定正式条件**：规模、结算周期、价格变更、暂停与退出。

测试成功并不自动意味着长期容量或响应承诺成立。

## 对账怎么做

供应合作里最常见的争议来自计量。建议从第一天起按下面的方式留痕：

- **双方各自记录**：需求方按请求记录接口返回的用量字段，供应方按自己的计量系统记录，按日汇总。
- **约定对账粒度**：按天、按模型汇总输入、输出和缓存 Token，差异超过约定比例时按请求核对。
- **失败请求怎么算**：超时、报错、取消的请求是否计费，在合作开始前写清楚。
- **价格变更**：提前多久通知、从哪一天起按新价格计，旧价格下的预付余额如何处理。

对账样例最好在测试阶段就跑一次，确认双方的数字能对上，再进入正式合作。

## 供应合作里常见的四个问题

- **只报一个总额度**：每月总量与每分钟、并发的限制是不同的约束，都要说明。
- **用个人账号或来历不明的密钥供应**：无法核验依据的资源，即使价格低也不适合长期合作。
- **测试时用生产密钥**：测试应使用独立凭据，限定权限和有效期。
- **不约定退出**：合作结束时剩余额度、未完成任务和日志如何处理，要在开始前写清楚。

## 常见问题

### 提供最低价格就能进入合作吗？

不能仅凭价格判断。还需要确认供应依据、可用范围、责任与结算口径，才能比较方案。

### 首次沟通要发账号和密钥吗？

不要。先发不含凭据的资源说明；后续确需技术验证时，再约定受控凭据、权限、时限与撤销方式。

### 资源只能短期提供可以吗？

可以，但要写明可提供周期和到期后的安排。短期资源适合补充峰值，不适合承载需要长期稳定的业务。
